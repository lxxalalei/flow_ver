# Inspection Guidance

Inspect 的语义职责是：**补充会改变当前判断的事实。**

## 1. 什么时候值得 Inspect

调用前先确认两个条件：

1. 当前存在一个会改变推荐、选择或获取决策的未知事实；
2. 运行时 Tool schema 表明当前候选支持相应 Inspect 路径。

仅提供搜索发现的平台候选，可以在用户选中明确公开 URL 后先通过 URL Import 建立当前进程句柄，再依据新返回的真实平台身份和能力决定后续 Inspect。

典型情况：

- 搜索摘要不足以判断候选是否真的相关；
- 同名、版本、作者、语言等关键事实不清楚；
- 用户明确要求公开访问、特定登录条件、特定格式或可获取性；
- 需要区分资源本体和 landing page；
- 某个未知事实会直接影响是否推荐或是否下载。

低潜候选、当前摘要已经足够支持决策、用户只是做初步浏览时，可以直接保留现有 Evidence。

## 2. Inspect 只补当前决策需要的事实

Inspect 围绕当前问题取证，例如：

- 是否为目标资源本体；
- 版本是否正确；
- 当前是否可访问；
- 是否存在用户真正需要的表示或格式；
- 是否有会改变推荐的失败或限制。

Inspect 的输出只作为当前 Evidence 使用。

## 3. 与下载的关系

用户尚处于发现或选择阶段时，Inspect 只服务于语义决策。

真正进入下载时，执行能力会再次确认当前资源事实，因此下载阶段以 fresh runtime result 为准。

## 4. 临时句柄失效时恢复同一资源

资源句柄来自平台搜索、创作者浏览或外部 URL 导入，只承担当前 MCP 进程内的操作定位。

句柄失效后按当前已知稳定身份恢复：

1. 已知原 URL → 直接用 URL 重新建立句柄；
2. 已知稳定平台标识 → 精确重新定位同一资源；
3. 已知标题 / 作者 / 平台 → 围绕该资源做最小定位；
4. 当前身份事实不足以确认原资源 → 重新进入发现阶段。

目标始终是恢复用户已经选中的同一资源。
