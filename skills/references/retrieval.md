# Retrieval Guidance

多轮检索的核心是：**让每次搜索都增加对用户目标有价值的新证据。**

## 1. 每轮围绕 Goal / Evidence / Gap 推进

```text
用户真正需要什么
  → 哪些学习价值还需要覆盖
  → 为这些价值设计什么搜索任务
  → 真实结果增加了什么 Evidence
  → 还缺什么内容或决策事实
  → 下一步是否存在明显不同且有价值的路线
```

这些都是当前对话中的即时判断。

## 2. 搜索路线按学习价值区分

例如：

```text
火山科普
火山知识
儿童火山知识
```

通常属于同一搜索空间。

更有实质差异的路线是：

```text
喷发原理理解
真实喷发过程观察
可打印实验活动单
```

路线数量由尚未满足的学习价值决定。窄任务由一条路线覆盖时直接推进；开放式或复合任务存在不同价值缺口时分别探索。

## 3. 首轮追求足够的信息增益

首轮帮助确认：

- 当前需求理解是否正确；
- 主要价值路线是否合理；
- 哪些来源对这些价值有直接匹配；
- query 是否能召回有用内容；
- 用户约束是否能够满足。

形式和来源开放时，多个有直接价值匹配的来源可以并行或连续参与召回。

例如“让孩子了解火山，形式不限”可以同时验证：

- OpenClaw `web_search`：专业 / 官方机制解释、图文和长尾材料；
- Bilibili：动画、中长讲解、实验演示；
- Douyin：短科普、短演示；
- CCTV：当真实影像或纪录片能补当前 Coverage 时参与。

来源参与由直接价值匹配决定。

## 4. OpenClaw `web_search`：跨生态发现

OpenClaw 原生 `web_search` 与 MCP `resource_search` 并列参与召回。

`web_search` 适合发现：

- 官方和专业机构页面；
- 博物馆、出版社、教育机构等长尾来源；
- 专业文章、教程、地图；
- PDF / PPT / worksheet 等文档；
- 尚未单独接入 MCP 的网页资源。

开放式资源研究、形式或来源开放、主要目标需要跨生态发现时，首轮通常包含 Web 路线。用户限定平台、已经给出具体 URL，或窄任务已被专门生态直接覆盖时，可以直接使用对应专门能力。

### Web Candidate 进入 MCP

`web_search` 结果先以 URL、标题、摘要/片段、域名和日期等证据参与候选判断。

具体 URL 在以下场景进入 MCP：

- 用户已经选中并要求保存、下载、归档或转换；
- 页面本体存在会改变推荐或获取决策的关键未知事实；
- 后续需要 Inspect / Download / HTML Design / Archive。

搜索证据已经足够支持推荐的 Web Candidate 可以直接展示。

### Web 与 MCP 候选语义去重

二者命中同一个实际资源时，使用当前可见 URL、平台稳定标识、标题和作者等事实判断是否为同一资源，并合并为一个语义候选。

## 5. 候选 Evidence 判断

重点看：

- relevance：是否围绕当前目标；
- usefulness：能否帮助用户完成目标；
- target fit：深度、语言、媒介是否合适；
- constraint fit：是否满足 must / exclude；
- substantive：是否有真实内容；
- credibility：当前任务所需证据是否足够；
- complementarity：是否与已有候选提供不同价值。

证据不足的事实保持 unknown。平台优势只作用于 routing，具体候选质量由当前真实 Evidence 判断。

Web snippet 只支持其实际显示的事实；页面结构、全文结论、文件格式和可获取性由页面本体或后续工具事实确认。

## 6. Gap 来自尚未满足的用户价值

### 内容 Gap

当前候选缺少用户明确需要的内容或用途，例如：

- 用户要“看懂过程”，当前只有背诵知识点；
- 用户要练习，当前只有讲解；
- 用户要可打印材料，当前只有视频；
- 用户要版本事实，当前只有泛化介绍。

### Coverage Gap

单条候选可能有价值，但当前候选集仍缺一个明显且重要的学习角色。

例如开放式火山学习资料目前只有短视频时，短视频可能已经完成“直观认识”，而可靠的结构化解释仍可能形成 Coverage Gap。

Gap 的成立条件始终是：**补上它会让 Goal 的覆盖产生实质提升。**

## 7. Next：每次补搜都说明新增价值

继续之前回答：

1. 当前具体缺什么；
2. 下一条路线准备补什么；
3. 新路线进入哪个实质不同的搜索空间；
4. 新 Evidence 可能怎样改变推荐、选择或停止判断。

能够明确说明新增价值时继续 Search / Inspect。

## 8. Stop：当前 Evidence 足够支持下一阶段

当主要学习价值已经获得足够好的候选、关键 must / exclude 已经能够判断、重要 Gap 已被覆盖，并且已经没有高信息增益的新路线时 Stop。

用户明确表示当前结果已经足够时，也直接进入选择或使用阶段。

Stop 表示当前 Evidence 足以完成本轮目标。

## 9. Inspect 只补决策事实

某个高潜候选存在会改变推荐或获取决策的未知事实时进一步 Inspect，例如：

- 版本、创作者或语言不清楚；
- 用户要求公开访问或特定格式；
- 需要确认资源本体与 landing page；
- 搜索摘要不足以支持关键判断。

对于 `web_search` 命中的 URL，页面本体事实确实会改变决策时再 Import / Inspect。

## 10. Selection 基于用户实际看到的候选

用户说“第 2 个”“这两个”时，把指代映射到用户实际看到且能够合理指代的候选。

稳定资源身份优先使用 URL、平台稳定 ID、标题、作者和来源。Web Candidate 已经展示 URL 时，用户选中后直接复用该 URL 进入 `resource_import_url`。

## 11. Browse 与 Enumerate 使用不同完成条件

Browse 关心代表性和判断价值；获取到足以刻画来源或支持选择的内容时完成。

Enumerate 关心数据完整性，例如：

- 某创作者全部作品；
- 某明确时间范围的完整内容；
- 用户明确要求导出全部列表。

Enumerate 使用结构化 Expand / Job 直到来源真实结束。聊天分页只控制展示量，完整性由来源终止信号和完整结果决定。

## 12. 平台技术失败更新当前 Evidence

平台搜索失败、认证失败或 partial failure 表示当前这条来源路线没有取得预期结果。

随后根据当前 Goal 判断：

- 该来源是否仍然关键；
- 是否存在同价值的合理替代来源；
- 是否值得重试；
- 当前已有 Evidence 是否已经足够进入 Stop。

技术失败作为路线事实进入 Evidence，内容结论继续由真实资源证据支持。
