# Source Routing Guidance

本文件回答一个问题：**哪些来源对当前学习价值有直接、具体的匹配，因此值得参与召回。**

运行时 Tool schema 和真实返回决定当前来源实际可用的搜索、读取与获取能力。

## 1. 路由从用户价值开始

按以下顺序判断：

1. 用户要完成什么；
2. 需要哪些内容形态、学习价值或证据角色；
3. 哪些来源对此存在直接价值匹配；
4. 在对应来源里，人会怎么搜。

来源优势作为搜索先验，用于判断参与价值、自然 query 和结果观察重点。具体候选的质量、公开性和可获取性由真实结果决定。

一个来源能够具体回答：

> 这个来源为什么有合理概率为当前 Coverage 提供有价值候选？

即可参与召回。多个来源可以竞争同一个 Coverage。

平台接入状态、用户身份和主题理论可表达性只作为背景；实际派发依据当前 Coverage 与来源能力之间的直接价值匹配。

搜索阶段偏 Recall，结果阶段偏 Precision。相近价值可以共享同一来源的一条自然 query，实质不同的搜索空间再拆分。

## 2. OpenClaw `web_search` 与专门生态

### `web_search`：开放互联网发现

OpenClaw 原生 `web_search` 负责跨站发现，包括：

- 官方和专业机构页面；
- 博物馆、出版社、学校、大学、研究机构等长尾来源；
- 专业文章、教程、地图；
- PDF / PPT / worksheet 等文档；
- 尚未单独接入 MCP 的网页资源。

典型触发：

- 形式或来源开放；
- 需要专业、官方、原始事实；
- 图文、文档、地图或长尾材料有直接价值；
- 当前目标需要跨生态发现；
- 用户明确要求网上找、网页资料或全网发现。

用户已经限定具体平台、给出具体 URL，或一个窄任务已经被专门生态直接覆盖时，可以直接走对应能力。

### Web Candidate 进入 MCP 的条件

`web_search` 返回的 URL、标题、摘要/片段、来源域名和日期先作为 Web Candidate 参与 Evidence 判断。

具体 URL 在以下场景进入 `resource_import_url`：

- 用户选中并要求下载、保存、归档或转换；
- 页面本体存在会改变推荐或获取决策的关键事实；
- 后续需要 Inspect / Download / HTML Design / Archive。

搜索证据已经足够支持推荐的 Web Candidate 可以直接呈现给用户。

### Web 与专门来源共同竞争

`web_search` 与 `resource_search` 并列参与召回。同一个 Coverage 可以同时由二者返回候选。

二者命中同一实际资源时，依据 URL、平台稳定标识、标题和作者等当前证据合并为一个语义候选，并保留更完整、后续更容易使用的证据。

## 4. 一个 Coverage 可以派发多个来源

例如：

```text
用户目标：让孩子理解火山并能直观看到喷发

Coverage A：形成 / 喷发机制
web_search：火山形成 喷发原理 科普
Bilibili：火山喷发 原理 动画 实验演示
Douyin：火山喷发 原理 科普

Coverage B：喷发过程观察
Bilibili：火山喷发 真实影像 动画
Douyin：火山喷发 现场 科普
CCTV：火山 喷发 纪录片
```

最终模型是：

```text
Coverage Need
  ↓
Direct Value Match
  ↓
Eligible Sources
  ↓
Reasoned Fan-out
  ↓
Real-result Competition
```

例如 SmartEdu 在“按小学科学教材找火山相关同步课”中有教材 / 同步 / 课时的直接触发信号；在开放式火山科普中则根据当前 Coverage 是否确实需要教材体系决定参与价值。

## 5. Query 适应来源生态

同一个主题在不同生态里使用自然 query：

```text
web_search：火山形成 喷发原理 科普
Bilibili：火山喷发 原理 动画 实验演示
Douyin：火山喷发 原理 科普 实验
CCTV：火山 喷发 纪录片
SmartEdu：小学科学 火山 同步课
```

评价词留给结果阶段；query 主要表达主题和当前切面。

同一来源的一条 query 已经能覆盖相近价值时直接共享；实质不同的 Coverage 再使用不同 query。

## 6. 来源集中只在暴露价值缺口时形成 Gap

开放式任务准备停止时，观察当前高潜候选是否仍缺一个对 Goal 有实质价值的内容形态、证据角色或来源能力。

例如当前只有大量火山短视频，而用户还需要可靠结构化解释，则结构化解释形成 Coverage Gap，可以补 `web_search` 或长解释路线。

Gap 始终由当前结果中尚未满足的价值定义；当已有 Evidence 足以覆盖 Goal 时进入 Stop。
