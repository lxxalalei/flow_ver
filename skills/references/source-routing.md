# Source Routing Guidance

本文件只回答一个问题：**不同发现方式和来源生态通常擅长提供什么学习价值。**

它不是平台能力表、登录状态表或下载说明书。当前到底能不能搜、能不能读、能不能下，以运行时真实工具结果为准。

## 1. 先区分通用发现层与专门生态

不要从“有哪些平台”开始。优先判断：

1. 用户真正要获得什么结果；
2. 这个结果需要哪种内容、资源形态或证据；
3. 哪些路线天然适合承担这些价值；
4. 是否需要跨生态发现，还是一个专门生态已经足够；
5. 在对应来源里，人通常会怎么搜索。

### Host Web Search：跨生态通用发现层

Host Web Search 不等同于某一个垂直平台，也不只是专门平台失败后的 fallback。

它的优势是跨站发现：

- 官方机构、专业组织和公共机构页面；
- 博物馆、出版社、学校、大学、研究机构等长尾来源；
- 专业文章、教程、地图、活动方案；
- PDF/PPT/worksheet 等文档；
- 未单独接入资源 MCP 的网站；
- 用户明确指定的网站或域名。

开放式任务首轮默认包含 Web Search 路线。下列情况是典型获益场景：

- 用户说形式不限、来源不限；
- 需要专业/官方解释或原始事实；
- 可能存在有价值的图文、文档、地图或长尾材料；
- 没有单一专门生态天然覆盖主要学习价值。

只有用户明确只要视频、只要教材同步课、只要某个平台时才跳过；跳过时心里能说出理由即可。

选中具体网页后，再进入资源检查或获取能力。

### 专门来源生态：聚焦召回

专门平台更适合在某类资源中做高密度召回，例如视频、音频、教材课程、文档或图书目录。

同一个搜索角度不必为了“多平台”重复派发多个高度同质来源；但当不同来源能提供不同证据、资源形态或可信度时，可以同时存在。

## 2. 常见专门来源生态

下面只是语义上的来源知识，不代表当前运行时一定可用。

### Bilibili / 视频生态

适合动画讲解、实验演示、真实过程、纪录片、系列课程、操作步骤等“需要看到”的内容。

如果用户只要可打印练习，视频没有独特贡献，就不应因为它常用而自动加入。

自然 query 往往强调画面价值，例如：

```text
火山喷发 原理 动画 实验演示
太阳系 八大行星 动画 小学
```

### SmartEdu / 结构化教育生态

适合同步课程、知识点讲解、教材体系、学段/学科明确的系统学习。

这类来源中，学段、学科、单元、教材版本通常比“优质”“精品”更有检索价值。

用户只是做课外兴趣探索时，不必机械加入同步课程。

### Zjer / 地方 K12 教育生态

适合地方优质课、课堂教学资源、特色课程和具体课时。

它与国家级教育来源职责有重叠；只有地方课程、具体课时或用户明确指定时才有明显独特价值。

### Ximalaya / 音频生态

适合朗读、故事、听书、跟读、音频课、连续专辑等听觉输入。

“路上听”“睡前听”“朗读”“听故事”等使用场景可以自然支持音频方向。

### Zhihu / 问答与经验生态

适合方法解释、经验比较、概念辨析、版本选择和资源线索。

它往往更适合帮助家长、学习者或规划者做判断，不自动等于孩子可以直接使用的学习材料。

### 专业科普 / 官方来源

适合需要较高可信度的科学、自然、健康、安全、政策或原始事实说明。

这类来源很多时候通过 Host Web Search 发现，而不是依赖某个固定 MCP 平台。

来源身份本身不能证明单条内容一定适合用户，但当任务对可信度要求高时，它们通常更适合承担主证据。

### CCTV / 公开课 / 公共媒体视频

适合纪录片、公开课、较完整的视频叙事和演讲。

是否过深、是否适龄、是否真正围绕当前目标，仍需看具体候选。

### Douyin / 短视频生态

适合短时间展示一个动作、步骤、技巧、实验现象或趣味切面。

不要默认让短视频承担完整知识体系；只有“短而直观”对当前目标有独特贡献时才使用。

### 图书目录 / NLC 等

适合书名、作者、版本、ISBN、馆藏和书目线索。

目录命中证明“发现了这本书”，不等于已经获得可阅读文件。

### 古籍 / 公版影印来源

适合中国古籍、公版影印本、版本线索和古籍原始材料。

特别适用于“找哪个版本”“查看原貌”“寻找公版影印”这类目标。

### LibGen 等图书发现来源

只在图书、电子书、版本线索确有价值并符合当前访问与版权边界时考虑。平台身份统一为 `libgen`，资源身份以 MD5 等平台稳定事实为准，获取路线只使用 LibGen mirror。

搜索命中与实际可获取是两件事，不要混为一谈。

### Baidu Wenku / 文档生态

适合课件、讲义、练习、文档、可打印材料等候选发现。

命中不证明免费、完整、无需登录或可下载；这些属于具体候选事实。

### Runoob / 技术教程生态

在编程和计算机主题下适合结构化中文教程和实例。

不要因为它是已知来源就用于非技术主题。

### Weibo / WeChat / 机构内容生态

适合机构发布、专题文章、活动材料和长尾线索，通常作为补充发现。

如果存在更原始的官方来源，不应因为社交平台更容易命中就自动替代原始证据。

## 3. 为价值派发来源，不为平台派发 query

同一个目标在不同来源中的 query 可以不同，因为它们承担的价值不同。

例如用户想让孩子了解火山：

```text
Host Web / 专业解释：火山形成 喷发原理 科普
视频观察：火山喷发 原理 动画 实验演示
Web/文档活动：火山 实验 活动单 小学生
```

而不是：

```text
平台A：儿童火山优质资料
平台B：儿童火山优质资料
平台C：儿童火山优质资料
```

常见互补关系包括：

- 原理解释 vs 过程演示；
- 同步讲解 vs 练习本体；
- 官方原始材料 vs 经验比较；
- 单篇朗读 vs 连续专辑；
- 网页理解材料 vs 可打印文件；
- 图书目录线索 vs 可阅读资源本体。

不要固定“一个角度只能一个来源”。如果两个来源承担的是不同证据角色，即使主题相同也可能都值得搜；如果只是同质召回，就没有必要为了数量重复。

## 4. Web 定向发现

当用户明确指定来源，或当前缺口是“需要高可信原始来源/具体文件”，可以用站点或文件类型约束缩小范围。

例如：

- 教材/教育政策 → 教育主管机构、教材出版机构；
- 汉字/古诗文 → 权威字典、古诗文专业整理来源；
- 科学健康安全 → 政府、公共卫生、专业科普机构；
- 历史文物 → 博物馆、档案馆、大学/研究机构；
- 明确文件 → PDF/PPT/文档定向搜索。

一条 query 尽量绑定一个明确目标，不要堆大量域名组成不可解释的 OR 列表。

## 5. 来源集中什么时候构成问题

准备停止开放式研究任务前，如果高潜候选全部集中在一种生态，可以问：

> 其他来源是否能提供当前候选明显缺少、且对用户目标有价值的内容？

如果能，应该把它视为 Coverage Gap，而不是因为已有几个好结果就停止。

如果不能，或者用户已经限定资源形态/来源，集中就不是问题。

例如：

- “火山学习资料，形式不限”只有 B 站视频 → 可能缺专业图文/活动材料；
- “给我几个火山真实喷发视频”只有视频 → 正常；
- “人教版五上同步课程”主要来自 SmartEdu → 可能完全合理。

## 6. 不要混淆三类判断

始终区分：

- **来源生态知识**：这个来源通常擅长什么；
- **当前能力事实**：这次运行是否能搜索/访问；
- **当前候选事实**：这个具体资源是否公开、完整、适合、可获取。

来源生态只帮助决定“为什么值得去这里找”，不能自动推出：

- 当前已经登录；
- 当前一定有结果；
- 某个候选免费或公开；
- 某个候选一定能下载；
- 某个平台当前一定可用。

这些都需要看真实工具结果。

## 7. 创作者内容

只有用户真正关心某个创作者/账号已有内容时，才进入创作者浏览或完整枚举。

“提到作者名字”不自动等于“浏览作者主页”；普通主题搜索也不应自动升级成 creator browse。

如果用户只是想挑几个代表性作品，小规模预览即可；如果明确要求全部作品，则应按完整枚举任务处理，不能把预览数量当成全量上限。
