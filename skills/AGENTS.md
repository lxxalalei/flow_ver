# skills/AGENTS.md

本文件补充根目录 `AGENTS.md`，约束 `skills/SKILL.md` 与 `skills/references/` 的运行时 Prompt 写法，以及相关 eval 用例如何反哺 Prompt。

## Prompt 规则

### 1. Mirrored TailQ

一条运行时规则应在主规则中一次性表达完整边界：**触发条件 → 应采取的动作 → 完成条件**。

如果主规则已经排除了某种情况，后面的尾句又专门否定同一情况；或者主规则从未排除某种情况，尾句又额外声明“这种情况也可以”，该尾句属于 Mirrored TailQ。

处理方式：把真正需要的边界合并进主规则，随后删除镜像尾句。最终 Prompt 保留一条完整、可直接执行的正向规则。

### 2. Dangling NegationQ

每一节最终只描述**当前仍然有效的决策空间、动作和状态**。

某个选项已经被上游架构、前文规则或当前状态排除后，后续规则直接围绕剩余有效选项表达；已经退出当前决策空间的历史选项放在架构记录、测试或 Git 历史中，而不继续作为运行时 Prompt 的否定对象。

处理方式：先确定当前有效状态集合，再用正向条件和动作重写规则；最终状态只保留 Agent 此刻真正需要考虑的内容。

## 从会话教训到 Prompt 的维护流程

单次会话暴露的问题优先沉淀为 eval / real-user-journey 用例。用例证明问题对应一个稳定、可复用的产品不变量后，优先修改现有正向规则，使其自然覆盖该情况。

新增运行时规则只用于表达现有规则无法覆盖的独立产品不变量。历史事故名称、旧架构名词和一次性补丁条件留在测试与开发记录中。

修改 Skill 或 references 后，检查：

1. 主规则是否已经完整表达触发条件、动作和完成条件；
2. 后一句是否只是在镜像主句的补集；
3. 当前段落是否仍提到已经退出决策空间的历史选项；
4. 这次改动是否可以通过修正已有正向规则覆盖；
5. 对应会话问题是否已有 eval 用例承接回归验证。
