# Download Guidance

下载阶段只处理一个语义问题：**用户是否已经明确要把哪个资源获取下来。**

## 1. 什么时候可以下载

只有用户已经明确表达“下载、保存、获取下来”等意图时才执行副作用。

例如：

- “第 1、3 个帮我下下来” → 对象和意图都明确，可以执行；
- “这本书能下的话帮我保存” → 已经明确要求获取，不需要再生成一份形式化计划让用户二次确认；
- “先看看”“先别下载” → 只做发现和判断，不执行下载。

如果用户指代的具体资源仍有歧义，先确认对象；如果对象已经清楚，不要重复确认已经明确的意图。

## 2. 用户选择是资源语义，不是临时句柄

Agent 应理解用户真正选中了哪个资源，并利用当前对话中已有的 URL、平台、标题、作者或稳定平台标识维持这个选择。

临时操作句柄只是执行工具的一部分。句柄失效时应重新定位同一资源，而不是重新做一遍资源研究。

## 3. 不替用户制造格式要求

默认优先获取资源原本合适的表示。

只有用户明确要求特定格式，且格式会影响实际使用时，才把格式作为获取条件。例如“我要能打印的 PDF”与“电子版都行”不是同一种约束。

不要为了后端统一强制转换格式，也不要把模型自己的偏好变成用户要求。

## 4. 成功只依据真实结果

只有工具实际产生可用文件，才能说下载成功。

以下都不能等同于成功：

- 已经开始任务；
- 理论上存在下载方式；
- 某个平台通常可以下载；
- Agent 预计能够成功。

认证失败、资源失效、部分失败等按真实结果说明，不伪装成功，也不静默切换到不等价资源。

## 5. 失败后的判断

失败后先判断失败属于哪一类：

- 当前资源暂时不可获取；
- 当前来源需要登录或授权；
- 资源本体已经失效；
- 只是某条获取路径失败，但仍有等价且用户可接受的真实表示；
- 用户真正需要的是替代资源，而不是继续折腾同一个文件。

是否寻找替代资源重新回到语义判断，不要由下载器自动决定。

## 6. 取消

用户明确要求停止正在进行的下载时，执行取消能力即可。

取消是用户意图，不需要额外设计一套工作流事务或确认链。
