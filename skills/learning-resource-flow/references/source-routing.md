# Source Routing Guidance

本文件只提供来源生态的语义知识。它不是平台 Registry、登录状态表或下载能力表；实际 platform ID、认证状态、Inspect/Acquire 能力以当前 MCP schema 和 Tool 返回事实为准。

## 1. 先决定需要什么，再决定去哪里搜

每个搜索角度按这个顺序判断：

1. 用户在这个角度需要获得什么结果？
2. 需要哪种内容/证据：视觉过程、系统课程、解释文章、练习本体、音频、图书版本、官方材料等？
3. 哪类来源最直接承担主召回？
4. 是否还有一个来源能提供明显不同的互补价值？
5. 在这个来源里，人通常会怎么搜？

同一个角度通常一个主力来源即可。两个平台大概率只会召回同质内容时，不为了“多平台”都搜。

## 2. 高频来源生态

以下只帮助判断“为什么值得搜这里”，不证明当前 runtime 能搜、能读或能下载。

- **视频生态（如 Bilibili、公共媒体）**：动画讲解、实验、真实过程、纪录片、操作步骤等需要画面理解的内容。
- **结构化教育生态（如 SmartEdu）**：同步课程、知识点、教材体系、学段/学科明确的系统学习。
- **音频生态（如 Ximalaya）**：朗读、故事、听书、跟读、音频课、连续专辑。
- **问答/经验生态（如 Zhihu）**：方法解释、经验比较、概念辨析、版本选择和资源线索；不自动等于孩子可直接使用的学习材料。
- **专业科普/官方 Web**：科学、自然、健康安全、原始说明等需要较高可信度的解释。
- **短视频生态**：适合短时间演示单个动作、步骤、实验现象或趣味切面，不默认承担完整知识体系。
- **图书目录/古籍生态（如 NLC、Shuge）**：书名、作者、版本、ISBN、馆藏、古籍和公版资源线索。目录或详情命中不自动证明当前可直接获取。
- **文档生态**：课件、讲义、练习、活动单、可打印材料等候选发现。命中不证明免费、完整或可下载。
- **技术教程生态（如 Runoob）**：只在编程/计算机主题下有结构化教程价值。
- **机构/社区内容生态（如公众号、微博等）**：专题文章、机构发布、活动材料和长尾线索，通常作为补充发现。
- **Generic Web**：官方机构、专业网页、长尾文章、具体文件、用户指定站点和未单独接入站点。

Generic 是 discovery 路线，不是 acquisition fallback。某个 Provider 获取失败时不能静默换成 Generic 获取。

## 3. Query 要体现来源职责

同一目标在不同来源中的 query 应该不同，因为它们承担不同价值。

例如“让孩子了解火山”：

```text
原理理解 / 专业科普：火山形成 喷发原理 科普
过程观察 / 视频：火山喷发 原理 动画 实验演示
```

而不是每个平台都搜：

```text
儿童火山优质资料
```

高质量差异来自真实目标，例如：

- 原理解释 vs 过程演示；
- 同步讲解 vs 练习本体；
- 官方原始材料 vs 经验比较；
- 单篇朗读 vs 连续专辑；
- 网页理解材料 vs 可打印文件；
- 图书版本线索 vs 可获取资源本体。

来源语言也应自然：

- 视频：过程、动画、实验、纪录片、操作；
- 音频：朗读、故事、跟读、听书、专辑；
- 教育平台：学段、学科、知识点、单元、真实教材版本；
- 图书来源：书名、主题、作者、版本、ISBN；
- Generic Web：主题 + 具体用途/内容切面，必要时 `site:` / `filetype:`。

每个平台首轮通常只发最有价值的一条聚焦 query。只有第二条代表真正不同的检索空间时才增加。

## 4. Generic Web 定向发现

用户明确指定来源，或当前缺口是“需要可信原始来源/具体文件”时，可以用 `site:` / `filetype:` 缩小范围。

例如：

- 教材/公共教育 → 教育主管机构、教材出版机构；
- 古诗文/汉字 → 专业字典、古诗文原始或专业整理来源；
- 科学健康安全 → 政府、公共卫生、专业科普机构；
- 可打印材料 → `filetype:pdf` 等具体文件发现。

域名只是 query 条件，不是新的 platform ID。不要堆很多域名形成难以解释的 OR 查询。

## 5. 三类事实不要混淆

1. **来源生态知识**：Skill 可以知道一个生态通常擅长什么；
2. **当前搜索能力**：由 MCP 当前 schema、Registry 和实际 Tool 返回决定；
3. **当前候选可获取性**：由 Inspect/Resolution/Representation 和 Provider runtime 决定。

来源生态不能直接推出当前已登录、有结果、免费公开、可下载或 Provider 可用。

具体平台的 URL 解析、认证、直链和下载规则属于 MCP/Adapter 机器事实，不在本文件复制。

## 6. Creator Browse

只有用户明确想浏览某个创作者/账号已有内容，并且当前 MCP 实际支持对应 creator browse 时，才使用 `resource_browse_creator`。

普通主题搜索、单条资源链接或只提到作者名字都不自动转换成 creator browse。Creator Browse 返回的仍是候选，后续照常判断、展示和选择，不是批量下载入口。
