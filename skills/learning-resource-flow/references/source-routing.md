# Source Routing Guidance

本文件只提供“不同来源生态擅长找什么”的语义知识。它不是平台 Registry、登录状态表或下载能力表；实际可用 platform ID、认证状态、Inspect/Acquire 能力始终以当前 MCP schema 和 Tool 返回事实为准。

## 1. 路由方法

不要从平台开始。按下面顺序判断：

1. 用户当前真正需要什么结果？
2. 这个结果需要哪种内容/证据：视觉过程、系统课程、长文解释、练习本体、音频、图书版本、官方原始资料等？
3. 哪类来源最适合承担主召回？
4. 是否还有一个来源能提供主来源缺失的明显互补价值？
5. 在这个来源里，人通常会怎么搜索？

同一个搜索角度通常 1 个主力来源即可；只有有明确互补价值时再补来源。两个平台大概率只会召回同质内容时，不为了“多平台”都搜。

## 2. 常见来源生态

以下只是 discovery 语义知识，不证明当前 runtime 能搜、能读或能下载。

### Bilibili / 视频生态

适合：动画讲解、实验演示、真实过程、纪录片、系列课程、操作步骤等“需要看到”的内容。

Query 应突出画面价值，例如：

- `火山喷发 原理 动画 实验演示`
- `太阳系 八大行星 动画 小学`

不因为主题是学习内容就自动搜 Bilibili；如果用户只要可打印练习，视频没有独特贡献。

### SmartEdu / 结构化教育生态

适合：同步课程、知识点讲解、教材体系、学段/学科明确的系统学习。

Query 更自然地使用学段、学科、知识点、单元和真实教材版本。用户只是想做课外兴趣探索时，不必机械加入结构化课程来源。

### Ximalaya / 音频生态

适合：朗读、故事、听书、跟读、音频课、连续专辑等听觉输入。

“路上听”“睡前听”“朗读”“听故事”等使用场景可以稳定支持音频方向。

### Zhihu / 问答与经验生态

适合：方法解释、经验比较、概念辨析、版本选择、资源线索和供家长/规划者理解的问题。

它通常不等于孩子可以直接使用的学习材料。资源对象是孩子时，先判断知乎内容在当前任务里是直接资源，还是只用于帮助家长做判断。

### Kepu / 专业科普生态

适合：科学、自然、健康安全等专业科普说明，可用于需要可信解释的方向。

高风险主题优先专业/官方来源，但平台身份仍不能自动证明单条内容正确或适配；具体候选仍需判断。

### CCTV / Open163 / Yixi 等公共视频与公开课生态

适合：纪录片、公共媒体内容、公开课、演讲等较完整的视频切面。是否适龄、是否过深、是否真正围绕当前目标仍需看具体结果。

### Douyin / 短视频生态

适合：短时间演示一个动作、步骤、技巧、实验现象或趣味切面。

不要默认让短视频承担完整知识体系；只有它对当前角度有独特的“短而直观”价值时使用。

### NLC / 图书目录生态

适合：书名、作者、版本、ISBN、馆藏和书目线索。

目录命中只证明发现了书目，不证明可以直接阅读或下载。

### Shuge / 古籍与公版影印生态

适合：中国古籍、公版影印本、古籍版本线索和相关资源发现。

具体详情 URL、直链和当前获取能力属于 MCP/Adapter 机器事实，不在 Skill 里复制规则；以实际 Tool 返回为准。

### Anna's Archive / 图书发现生态

只在图书、电子书、版本线索等发现确有价值并符合当前访问/版权边界时考虑。搜索命中不等于当前允许或能够获取资源本体。

### Baidu Wenku / 文档生态

适合：课件、讲义、练习、文档、可打印材料等候选发现。

命中不证明免费、完整、无登录限制或可以下载；这些是后续事实问题。

### Runoob / 技术教程生态

仅在编程/计算机主题下提供结构化中文教程和实例价值。不要因为它是已接入平台就用于非技术主题。

### Weibo / WeChat / 机构内容生态

适合：机构发布、专题文章、活动材料和长尾线索。通常作为补充发现，不自动替代原始官方来源。

### Generic Web

适合：

- 官方机构和专业网页；
- 长尾文章、教程、活动方案；
- 具体 PDF/PPT/文档；
- 未单独接入平台的网页资源；
- 用户明确指定的网站。

Generic 是 discovery 路线，不是 acquisition fallback。专门 Provider 失败时不能因为“Web 看起来也能下”就静默换成 Generic 获取。

## 3. Query 要体现来源职责

同一目标在不同生态中的 query 可以不同，因为它们承担的价值不同。

例如用户想让孩子了解火山：

```text
专业科普方向：火山形成 喷发原理 科普
视频方向：火山喷发 原理 动画 实验演示
```

不是：

```text
平台A：儿童火山优质资料
平台B：儿童火山优质资料
平台C：儿童火山优质资料
```

常见差异可以来自：

- 原理解释 vs 过程演示；
- 同步讲解 vs 练习本体；
- 官方原始材料 vs 经验比较；
- 单篇朗读 vs 连续专辑；
- 网页理解材料 vs 可打印文件；
- 图书目录线索 vs 可获取资源本体。

每个平台首轮通常只发一条最有价值的聚焦 query。只有两个检索范围确实不重叠时才考虑第二条。

## 4. Generic Web 定向发现

当用户明确指定来源，或当前缺口确实是“需要高可信原始来源/具体文件”，可以使用 `site:` / `filetype:` 缩小范围。

例如：

- 公共教育/教材：教育主管机构、教材出版机构；
- 汉字/古诗文：权威字典、古诗文原始/专业整理来源；
- 科学健康安全：政府、公共卫生、专业科普机构；
- 具体材料：`filetype:pdf`、`filetype:ppt` 等。

不要把域名当 platform ID；如果是 Generic Web 定向发现，仍使用 MCP 实际支持的 Generic 平台，并把站点限制放进 query。

一条 query 通常绑定一个明确站点/文件目标即可，不要堆很多域名把检索变成不可解释的 OR 列表。

## 5. 不要混淆三类事实

- **来源生态知识**：Skill 可以知道某平台通常擅长什么；
- **当前搜索/会话能力**：由 MCP 当前 schema、Registry 和实际返回决定；
- **当前候选可获取性**：由 Inspect/Resolution/Representation 和 Provider runtime 决定。

来源生态只能帮助决定“为什么值得搜这里”，不能直接推出：

- 当前已经登录；
- 当前有结果；
- 当前候选免费/公开；
- 当前能下载；
- 当前 Provider 可用。

这些都必须看 MCP 当前事实。

## 6. Creator Browse

只有用户明确想浏览某个创作者/账号已有内容，并且当前 MCP 实际支持对应 creator browse 时，才使用 `resource_browse_creator`。

单个资源链接、只提到作者名字、或普通主题搜索都不自动变成 creator browse。

Creator Browse 返回的仍是候选结果，后续和普通搜索一样需要判断、展示和选择；它不是批量下载入口。
