# Conversation Guidance

本文件只补充主 Skill 中较复杂的需求理解、用户背景和澄清边界。普通请求优先按 `SKILL.md` 直接理解并搜索，不要因为存在本 reference 就增加提问步骤。

## 1. 当前任务只关心什么

资源任务只需要理解：

- `goal`：用户真正想完成什么；
- `user_role`：当前对话者，可 unknown；
- `resource_target`：资源实际给谁/用于什么，可 unknown；
- `constraints`：会影响当前结果的 must / prefer / exclude。

这些是帮助理解任务的业务信息，不是要填满的槽位。`user_role` 与 `resource_target` 相互独立，不能互推；未知且不影响路线时保持未知。

## 2. 使用 OpenClaw 已有背景，但不要建立第二份画像

年龄、年级、家庭成员关系、长期偏好、基础水平等背景由 OpenClaw 上层上下文/记忆负责，不属于资源 MCP 的画像状态。

当前上下文已经可靠提供、并且与本次 resource target 明确对应的背景，可以在**确实会改变搜索或候选判断**时直接使用。例如：

- 已知小宝 8 岁，本次明确“给小宝找火山纪录片”时，可以用 8 岁判断内容尺度，不再重复问年龄；
- 已知大宝 12 岁、小宝 7 岁，本次明确给小宝找资料时，只使用小宝背景；
- 如果只说“给孩子找青春期科普”，而两个孩子会导致完全不同内容尺度，只问这次给谁，不重新采集已有年龄。

不要：

- 从 ResultSet、Archive 或候选内容反向推断用户画像；
- 把本轮模型为了召回提出的动画/纪录片等假设写成长期偏好；
- 新增 `target_age`、`child_profile`、`audience_profile` 等 MCP 状态来复制上层上下文。

## 3. 区分用户事实和搜索假设

当前语义判断至少区分三种来源：

- **explicit**：用户直接表达或确认；
- **inferred**：可由当前表达稳定推出，例如“路上听”支持音频方向；
- **exploration hypothesis**：模型为了提高发现质量提出的角度、内容形态或来源，只用于当前搜索。

探索假设不是用户偏好。例如用户说“恐龙资料，形式你决定”，你可以探索动画 + 图文，但不能据此声称“用户/孩子喜欢动画”。

新的明确修正覆盖旧推断。保持约束强度：must 不弱化，prefer 不升级成 must，exclude 不扩大否定范围。

## 4. 澄清的唯一理由：答案会改变路线

提问前先比较“不同答案会不会让我去找完全不同的东西”。

值得问：

- “物理启蒙”但不知道是学龄前、小学还是初中；
- “一年级数学资料”可能指同步讲解、基础练习或趣味拓展，而当前没有其他线索；
- 教材同步资源缺版本/册次；
- “这本书”存在多个会影响获取的版本；
- 多个资源对象的背景不同，本次对象不明确；
- 用户给出的硬条件彼此冲突，例如“不要视频，最好动画讲解”。

通常不值得问：

- 用户已经给出主题、对象/学段和用途，可以通过 1–2 个互补方向探索；
- 用户说“先看看”“都可以”“你决定”；
- 可以通过 Search/Inspect 直接确认的资源事实；
- 只是为了知道平台、数量、精确年龄、文件格式而提问，但这些并不会改变当前首轮搜索。

澄清是自然对话，不是表单。尽量问一个能最大幅度缩小路线的问题；如果两个问题彼此强相关且必须一起知道才能避免明显无效搜索，可以一次问清，但不要列字段清单。

用户回答后重新理解完整目标。比如“8 岁”意味着内容深度可能变化，不是仅记录 `age=8` 后继续原计划。

如果两轮高价值澄清后仍存在次要不确定性，通常用当前最佳理解搜索一轮，让真实结果帮助继续判断，而不是无限提问。

## 5. 不要混淆资源语义

区分：

1. **使用载体**：视频、音频、文章、图书、课程、练习等；
2. **内容形态**：动画、纪录片、绘本、朗读、试卷、课件、实验、观察卡等；
3. **文件格式/表示**：PDF、PPTX、DOCX、EPUB、MP3、MP4、HTML 等。

“电子版”“可打印”“高清”“可下载”通常是约束，不是格式。

例如：

> 要能打印的鸟类观察卡，最好 PDF。

应理解为：观察卡是内容形态；可打印是 must；PDF 是 prefer。不要把它变成“鸟类主题，所以也找视频”。

## 6. 问题驱动请求先理解结果，不做未经证据的诊断

用户描述一个学习困难时，先还原他希望改善的结果，不自动诊断原因。

例如：

> 看历史故事记不住人物关系。

优先理解为希望建立人物关系、时间线或叙事结构，再搜索相关材料；不要擅自判断是记忆力、注意力或其他问题。

安全、健康、心理等主题提高可信来源和内容适配要求，但主题本身不自动推出“必须问年龄”。只有年龄/阶段确实会改变内容安全性或可理解性时才问。

## 7. 面向用户的表达

内部可以做复杂判断，但不要把这些内部术语直接展示给用户。用户通常只需要看到：

- 必要的一个自然澄清问题；
- 简短说明你准备重点找什么（当这能帮助用户理解搜索范围时）；
- 真正值得选择的候选及差异；
- 当前不确定或受限的事实；
- 下载前的实际计划和明确确认问题。

不要让用户理解 `Flow`、`ResultSet`、`Presentation`、`Selection`、`representation_id`、digest 或 Provider 内部名才能完成任务。
