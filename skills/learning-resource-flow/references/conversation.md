# Conversation Guidance

本文件只负责用户需求理解、澄清和面向用户的表达。搜索、Inspect、获取和归档规则分别见对应 reference。

## 任务模型与语义上下文

MCP Task 只维护四项当前资源任务需要的业务输入：

- `goal`：用户真正想完成的学习/资源目标；
- `user_role`：当前对话者身份，可未知；
- `resource_target`：资源实际给谁/用于什么，可未知；
- `constraints`：用户明确表达或有充分证据支持的 must / prefer / exclude。

`user_role` 与 `resource_target` 相互独立，不能互相推导。未知信息保持 unknown，不为了填满字段而追问。

年龄、年级、家庭成员关系、长期偏好、基础水平等用户背景不属于本资源系统的画像状态。本 Skill 只消费 OpenClaw 当前会话或其上层用户记忆/上下文已经提供的可靠背景；不为这些背景建立新的 MCP 字段、Profile、Schema、持久状态链，也不负责写入、更新、过期或合并 OpenClaw 的长期记忆。

搜索前可以在当前可见上下文中按需考虑：

- 用户真正想解决的问题和期望结果；
- 资源由谁实际使用；
- OpenClaw 当前上下文已经提供、并且与当前资源对象明确对应的年龄、年级、基础水平或学习阶段；
- 使用场景；
- 用户明确要求的资源载体、内容形态或文件格式；
- 版本、语言、来源等会改变候选范围的条件；
- 搜索是普通推荐还是明确要求全面比较。

只考虑会实际改变 SearchDirection、来源、query、候选判断或后续获取的信息。没有影响的维度保持未知，不补齐。

## 上层用户背景的消费边界

本 Skill 不维护家庭画像，只使用当前已经可见且来源可靠的背景。

- 当前上下文已经明确某个资源对象的背景，且本次仍明确指向同一对象时，可以直接使用，不要求用户在每个新搜索里重复声明；
- 当前上下文没有该背景时，不从资源 MCP、历史 ResultSet、Archive 或候选内容反向推断用户画像，也不为了“以后方便”主动采集；
- 模型在当前任务中的推断、召回假设或候选特征不能自动写回长期用户记忆；是否沉淀为 OpenClaw 用户背景由上层记忆机制负责；
- 多资源对象时不能串用背景。例如 OpenClaw 当前上下文已知“大宝 12 岁、小宝 7 岁”，用户说“给小宝找资料”时只使用小宝的背景；如果只说“给孩子找”而不同对象会导致明显不同路线，优先澄清这次给谁，而不是重新采集已经存在的年龄；
- 如果 OpenClaw 当前上下文没有稳定背景，也不要假定它“应该存在”或为了读取记忆而绕过本 Skill 的正常工具边界。

不要把年龄特殊化：

- 当前上下文已知且相关：使用；
- 已知但无关：不必塞进 query；
- 未知且通常不影响当前搜索：不问；
- 未知且会实质改变内容尺度、学习路线或候选适用性，并且一轮有界探索无法合理覆盖：才问一个最小必要问题。

安全、健康、心理等主题可以提高可信来源和内容适配的审查要求，但“主题敏感”本身不自动推出“必须问年龄”。同样，也不能因为过去曾过度询问年龄，就写成“任何情况下都不要问年龄”。

## 证据与约束强度

区分当前任务事实的来源，不把模型自己的推断或默认伪装成用户说过的话：

- `explicit`：用户直接表达或确认；
- `inferred`：可以由明确表达稳定推出，例如“路上听”可以支持音频方向；
- `defaulted`：为了继续任务采用的低风险默认，例如普通中文对话先搜索中文内容。

OpenClaw 上层提供的用户背景可以参与当前语义判断，但除非用户在本次任务明确把它设为 must / prefer / exclude，不要把背景本身改写成本次新声明的硬约束。

新的明确修正覆盖旧推断。短回答结合刚才的问题理解，未受影响的已确认条件继续有效；出现事实或硬约束冲突时，不自行挑一个版本。

保持用户表达的约束强度：`must` 不得弱化，`prefer` 不得擅自升级成必须，`exclude` 的否定范围不得扩大。只有有充分依据且会影响任务的内容才进入工具参数。

模型为了扩大召回提出的资源形态、学习方式、内容切面或来源方向属于**召回假设**，不是用户事实。可以用于 SearchDirection 和 query，但不能反写成用户偏好或硬约束。

## 资源语义

不要把以下三层混为一谈：

1. **使用载体**：视频、音频、文章、图书、文档、课程、练习、互动或活动；
2. **内容形态**：动画、纪录片、绘本、朗读、试卷、课件、实验、活动方案等；
3. **文件格式/表示**：PDF、PPTX、DOCX、EPUB、MP3、MP4、HTML 等已确认格式。

“电子版”“可打印”“高清”“可下载”通常是用户约束，不是文件格式。上下文不足时保留用户原词，不强行把“绘本”“课程”“课件”等跨媒介概念归进一个固定类型；用户未指定形态时也不要替用户补成固定的视频、文档或课程偏好。

问题驱动型请求先还原用户真正想解决的问题，再规划资源。例如“看历史故事记不住人物关系”首先是希望建立人物关系和时间线，不应仅按“历史”主题做泛搜索，也不能擅自诊断原因。

## Ready 判断

开始搜索前只检查两个问题：

1. 当前信息能否形成方向明确、不会明显偏离用户诉求的首轮搜索路线？
2. 搜到候选后，当前信息是否足以判断哪些结果更符合目标和硬约束？

两个答案都是“能”就直接搜索，不为补齐身份、年龄、年级、平台、普通格式等辅助信息追问。若答案为“不能”，只澄清对路线或判断影响最大的一点。

“主题宽”本身不是澄清理由。需要区分：

- **宽但可探索**：1–2 个 SearchDirection 可以低成本覆盖主要可能性，先搜索；
- **路线实质分叉**：存在几条代表不同用户目标的路线，会显著改变 query、来源、候选类型或筛选标准，而首轮少量方向无法合理同时覆盖，先澄清最关键路线。

例如“一年级数学资料”可能明显分为课内同步、基础练习、趣味拓展；若用户没有授权“都可以/先看看”，可以问一次路线问题。相反，“古埃及文明资料，先看看”可以先用互补方向探索，不需要让用户先选视频、文章或平台。

## 什么时候澄清

只有缺失或冲突信息会显著改变以下任一项时才澄清：

1. 用户真正要解决的问题或搜索路线；
2. 硬约束；
3. 资源对象、版本或适用阶段；
4. 候选是否可接受或可比较。

典型需要澄清：

- 核心主题或问题无法确定；
- 多个彼此独立目标无法由一组候选合理覆盖；
- 宽泛请求存在实质不同的学习路线，且用户没有授权模型先探索；
- 教材同步但缺少会改变资源范围的版本/册次；
- 用户给出互斥 must 条件；
- 多个资源对象的背景不同，而本次对象不明确且会改变结果；
- “这本书/这个课程”存在多个无法区分且会改变获取结果的版本。

典型不应澄清：

- 仅为了补齐年龄、年级、身份等字段；
- OpenClaw 当前上下文已经提供的背景只是没有在当前消息重复；
- 仅为了选择平台或数量；
- 用户已经授权“都可以”“先看看”“你决定”；
- 宽泛主题可以通过少量互补 SearchDirection 有界探索；
- 可以通过 Search/Inspect 直接确认的资源事实。

一次只问一个最小必要问题。优先问真正决定路线的内容，不先问平台、数量或普通格式。若少量自然选项能降低回答成本，可以给 2–3 个方向，同时允许用户自由回答。不要要求用户填写内部字段、选择平台参数或提供 JSON。

需求足够时直接搜索；搜索本身不需要用户确认。

## 面向用户的表达

- 首轮搜索前可以用一句自然语言概括“准备找什么 + 当前最重要的限制”，然后直接行动；除非用户要求，不展示内部 query、平台调度、Tool 参数或计划字段。
- 优先说资源差异、证据、限制和下一步，不暴露内部 Tool、Flow、Plan、Job 或内部 ID。
- 搜索候选称为“候选”或“找到的资源”，不要把未展示 ResultSet 说成用户已经看过的结果。
- 未核验时使用“看起来”“搜索结果显示”；经过 Inspect 或服务端确认后再使用“已确认”。
- landing page、metadata、representation 与 primary resource 必须按真实能力解释，不把“能打开页面”说成“能下载正文/视频本体”。
- `queued`、`running`、partial、AUTH_REQUIRED、blocked、unsupported 都保留真实状态，不改写成成功。
- 用户作出选择和明确确认前，不替用户选择，也不启动下载副作用。
- 失败时先说明真实发生了什么，再给一个与当前事实相符的可执行下一步；不要用内部异常堆栈、乐观猜测或未经声明的 fallback 掩盖失败。

## 失败与恢复

工具响应丢失、上下文压缩、OpenClaw/MCP 重启或当前状态不确定时，优先读取 `resource_flow_status` / `resource_job_status` 等服务端事实；不要从聊天文本猜测业务状态。

需要认证时说明原因并交给合法的 session-manager 流程；不要索取账号、密码、验证码或 MFA。用户主动提供合法 Cookie/Token，并明确指定受支持平台、用途和保存授权时，只能将原值一次性直送 `resource_session_save`，不得复述、展示、记录、转发或失败后自动重放。
