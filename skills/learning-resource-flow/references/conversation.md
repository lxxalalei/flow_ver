# Conversation Guidance

本文件只补充资源任务中容易出错的需求理解与澄清判断。它不是用户画像 schema，也不是提问清单。

## 1. 当前任务只需要理解会改变决策的信息

优先还原：

- 用户最终想完成什么；
- 资源实际给谁使用；
- 哪些背景会改变内容尺度；
- 哪些条件是 must / prefer / exclude。

这些只是当前任务的语义。未知且不会改变搜索路线的信息可以继续未知，不需要补齐。

例如“我想给孩子找恐龙资料”中，对话者可能是家长，但资源对象是孩子。候选判断应该围绕孩子能否使用，而不是自动转成“家长怎么教恐龙”。

## 2. 复用上层已有背景，但不要建立第二份画像

如果 OpenClaw 当前上下文已经可靠提供与本次对象明确对应的年龄、年级、基础水平或长期偏好，而且这些信息确实会改变搜索或候选判断，可以直接使用，不要重复询问。

但不要：

- 把上层背景复制成资源 MCP 的 profile 状态；
- 从搜索结果反向推断用户画像；
- 把模型为了当前召回提出的动画、纪录片等探索方向写成长期偏好；
- 在多对象场景里把一个人的背景套给另一个人。

## 3. 区分用户事实、合理推断和探索假设

至少区分三类信息：

- **用户明确表达**：例如“先不要视频”“要能打印”；
- **当前表达可稳定推出**：例如“路上听”可以自然支持音频方向；
- **模型探索假设**：例如用户说“形式你定”，模型选择先试动画 + 图文。

探索假设只是搜索策略，不等于用户偏好。

新的明确修正覆盖旧推断。约束强度不要擅自改变：prefer 不能升级成 must，exclude 也不能扩大成用户没说过的全面否定。

## 4. 澄清的判断标准：答案是否会改变路线

值得问的问题通常会决定“接下来到底去找哪一类东西”。例如：

- “物理启蒙”面向学龄前、小学还是初中；
- “一年级数学资料”更需要同步讲解、基础练习还是趣味拓展；
- 教材同步资料缺少真正影响内容的教材版本；
- 多个孩子背景差异很大，但用户只说“给孩子找”；
- 用户给出的硬约束互相冲突。

通常不值得问：

- 平台偏好，但平台并不会改变首轮目标；
- 精确数量，只是为了填字段；
- 文件格式，而用户实际要的是“可打印”这类用途约束；
- 已经可以通过搜索或 Inspect 直接确认的资源事实；
- 用户已经明确说“你决定”“都可以”“先看看”。

澄清应该像自然对话。优先问一个最能缩小路线的问题，而不是一次列出年龄、年级、平台、格式、数量等字段清单。

如果高价值澄清后仍有次要不确定性，通常先按当前最佳理解搜索一轮，让真实结果帮助判断，不要无限追问。

## 5. 不要混淆内容、载体和格式

区分：

1. **使用载体**：视频、音频、文章、图书、课程、练习；
2. **内容形态**：动画、纪录片、绘本、朗读、试卷、课件、实验、观察卡；
3. **文件格式**：PDF、PPTX、DOCX、EPUB、MP3、MP4、HTML。

例如：

> 要能打印的鸟类观察卡，最好 PDF。

更合理的理解是：

- 观察卡：内容形态；
- 可打印：must；
- PDF：prefer。

不要因为主题是鸟类就自动增加视频，也不要把 PDF 从偏好升级成唯一允许格式。

## 6. 问题驱动请求先还原目标，不做未经证据的诊断

用户描述学习困难时，先理解他希望改善什么结果。

例如：

> 看历史故事记不住人物关系。

优先理解为需要人物关系、时间线或叙事结构辅助材料，而不是自动诊断记忆力、注意力或其他问题。

健康、安全、心理等主题可以提高来源可信度和内容适配要求，但只有年龄/阶段确实会改变内容安全性或可理解性时才需要追问。

## 7. 用户已经明确行动意图时不要重复确认

“先看看”“先别下载”意味着当前只做发现和判断。

“第 2 个帮我下载”“这本书能下的话保存下来”已经构成明确的获取意图。只要资源对象没有歧义，就直接进入真实获取能力，不再额外生成形式化计划要求用户二次确认。

只有当对象或意图本身仍不清楚时才继续确认。

## 8. 面向用户的表达

内部可以做复杂判断，但用户通常只需要看到：

- 真正必要的一个澄清问题；
- 简短说明当前重点找什么（仅在有帮助时）；
- 值得选择的候选及差异；
- 重要但尚未确认的事实；
- 用户要求获取后，真实执行结果。

不要向用户暴露后端内部对象或要求他理解工具实现才能完成任务。
