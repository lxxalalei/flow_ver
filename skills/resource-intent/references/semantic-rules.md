# Intent 语义理解与推断规则

## 1. Intent 的业务目标

Intent 不是分类器，也不是搜索器。它把家长或学习者的口语表达还原为下游能够使用的需求语义：学习对象、学习目标、学习者条件、资源偏好和不可违反的约束。

处理时先理解用户真正想解决的问题，再决定如何归一化字段。不要先套分类再解释用户。

## 2. 常见需求表达类型

### 直接资源型

用户已经说清资源对象：

- “四年级数学课程”
- “想要恐龙科普动画”
- “找适合睡前听的英语故事”

直接抽取主题、年级、形式和场景，通常无需澄清。

### 问题驱动型

用户描述问题，没有直接说资源名称：

- “孩子计算总是粗心” → 目标可能是计算习惯、检查方法和专项练习。
- “应用题不知道从哪下手” → 目标是应用题审题和解题思路。
- “孩子不敢开口说英语” → 目标是口语启蒙、跟读和低压力表达。

将问题翻译为可学习的目标，但不要擅自诊断原因。证据不足时保留多个 related terms。

### 能力培养型

- “想培养专注力”
- “提高表达能力”
- “训练逻辑思维”

如果能力方向已经明确，可以搜索活动、训练和方法资源；只有能力名称过于宽泛且可能涉及多种路线时才澄清使用目标或场景。

### 内容主题型

- “想让孩子了解中国历史”
- “最近对太空很感兴趣”

核心主题明确时不要求用户先选课程、动画、书或音频。资源形态可动态覆盖。

### 多目标型

用户同时提出多个相关目标时，保留主目标和相关概念：

- “学古诗，还想练朗诵” → core_topic 为古诗学习，朗诵进入 learning_goal/use_scenario 或 related terms。
- “数学计算和应用题都需要” → core_topic 可概括为数学基础练习，canonical terms 同时保留两项。

完全独立的多个目标不要强行合并；在 ambiguity 中说明需要拆成多个搜索计划，必要时让 flow 确认先处理哪一个。

## 3. 槽位定义

| 槽位 | 语义 | 典型来源 |
|---|---|---|
| `core_topic` | 用户真正要学习、练习或解决的核心对象 | 主题词、问题描述、明确目标 |
| `learning_domain` | 数学、语文、英语、科学、艺术等上位领域 | 从 core_topic 归纳 |
| `target_age` | 年龄或年龄范围 | “5岁”“低龄”“小学生” |
| `grade_level` | 学段和年级 | “三年级”“小学高年级” |
| `learning_goal` | 启蒙、预习、同步、复习、练习、提高、拓展、解决问题 | 动词、问题描述、使用目的 |
| `difficulty` | 启蒙、基础、同步、进阶、竞赛、不限 | “零基础”“提高题”“奥数” |
| `resource_types` | 视频类、音频类、文档类、练习类、图文类、图片类等资料大类 | 用户明确类型，或由明确形态/场景可靠归纳 |
| `format_preferences` | 动画、纪录片、公开课、试卷、练习册、绘本、课件等具体内容形态 | 用户明确形态，或由使用场景可靠推断 |
| `file_formats` | PDF、PPTX、DOCX、EPUB、MP3、MP4 等实际文件格式 | 用户明确文件后缀或格式名称 |
| `use_scenario` | 自主学习、亲子共读、路上听、打印练习、课堂辅助等 | 时间、地点、使用者和动作 |
| `version` | 教材、课程或软件版本 | 人教版、北师大版、上册等 |
| `language` | 资源呈现语言 | 中文讲解、全英文、双语等 |
| `search_mode` | standard / exhaustive | “推荐几个”或“尽量全面” |

来源要求直接按强度写入 `constraints.must` 或 `constraints.prefer`，不再维护重复的 `source_preferences` 槽位。

## 4. 从口语到学习目标

| 用户表达 | 可推断 learning_goal | 不应额外推断 |
|---|---|---|
| “练练手”“刷几道题” | 练习 | 竞赛难度 |
| “跟不上”“基础不牢” | 基础巩固 | 具体薄弱知识点 |
| “提前学下学期” | 预习 | 教材版本 |
| “最近很感兴趣” | 兴趣拓展 | 系统课程需求 |
| “考试前复习” | 复习 | 必须要试卷，除非用户明确 |
| “完全没接触过” | 启蒙 | 目标年龄 |
| “想系统学” | 系统学习 | 指定平台 |

推断时保留原始问题证据，不把模型解释写成用户原话。

## 5. 证据与状态

### explicit

用户直接表达或确认：

- “四年级” → grade_level explicit。
- “不要视频” → constraints.exclude explicit。
- “最好官方” → constraints.prefer explicit。

### inferred

由语义或稳定关系推出：

- 四年级 → 约 9-10 岁，但 target_age 必须标 inferred。
- 路上听 → 音频偏好 inferred。
- 练习题 → learning_goal=练习 inferred。
- 动画 → resource_types 包含视频类 inferred，同时 format_preferences=动画 explicit。
- PDF 试卷 → resource_types 包含文档类和练习类 inferred；试卷与 PDF 分别保留在具体形态和文件格式中。

### defaulted

为了继续工作采用的低风险策略，不代表用户事实：

- 未指定搜索广度 → search_mode=standard。
- 普通儿童资源且无语言提示 → 可默认中文，但英语学习场景需谨慎。

资料类型、具体形态和文件格式不得仅因主题而 defaulted。用户说“形式都行”是明确授权，`resource_types=["不限"]` 应标记 explicit；多形态覆盖由 Search 规划。

### 未知值

没有足够依据时省略槽位：

- 主题明确但没年龄 → 省略 target_age。
- 用户未提教材版本 → 省略 version。
- “英语启蒙”但没说讲解语言 → 省略 language，或采用低风险 defaulted；不得标 explicit。

## 6. must、prefer、exclude

### must

不满足就不应进入最终候选：

- “只要免费的”
- “必须带答案”
- “一定要可打印”
- “只要人教版”

### prefer

可以妥协但应影响排序和路由：

- “最好带答案”
- “优先官方”
- “有动画更好”
- “尽量短一点”

### exclude

明确不接受：

- “不要视频”
- “不要付费”
- “别推荐短视频”
- “不需要家长课程”

否定范围必须精确。“不要太难”通常是难度偏好，不等于排除所有进阶内容；“不想只看视频”也不等于完全排除视频。

## 7. 冲突处理

- 年龄与年级冲突：两者都保留 explicit，记录 ambiguity，通常需要澄清。
- “只要免费，付费也可以看看”：must 语义冲突，需要澄清真实底线。
- “不要视频，最好是动画”：形式冲突，需要澄清。
- “官方优先，也接受老师经验”：不冲突，官方是 prefer，用户内容仍可作为补充。
- 历史上下文与当前请求冲突：当前请求优先，但用户已确认事实需要明确更新后才能覆盖。

## 8. 动态默认策略

默认不是固定模板，应考虑主题和场景：

- 未指定来源的教材同步：可默认官方优先。
- 未指定来源的经验方法：可覆盖专业机构和用户经验。

年龄、年级、教材版本、付费接受度、资料类型和文件格式不要使用固定默认。主题适合哪些资料形态属于 Search 的召回策略，不是用户事实，Intent 不把它写入槽位。

每个 defaulted 槽位都要在 assumptions 中解释。

## 9. Search 概念边界

Intent 输出概念材料，不输出查询任务：

```json
{
  "canonical_terms": ["小学四年级", "数学", "课程"],
  "synonyms": ["解决问题", "文字题"],
  "related_terms": ["审题", "解题思路", "专项练习"]
}
```

canonical terms 不得丢失用户核心语义；synonyms 是等价或近似表达；related terms 用于拓展但不能替代核心主题。

不得在这里选择平台、拼接完整搜索句或写 `site:`。

## 10. 输出前语义自检

1. core_topic 是否描述了用户真正想学或解决的对象？
2. 是否把问题描述误当成诊断结论？
3. explicit 是否都有原话证据？
4. inferred 是否与 explicit 分开？
5. defaulted 是否低风险且写入 assumptions？
6. 没有依据的槽位是否被错误填成看似完整的值？
7. must/prefer/exclude 是否保持了语气强度？
8. 是否还有会让 Search 走向完全不同路线的歧义？
9. 是否错误生成了平台或查询任务？
10. 是否把资料大类、具体内容形态和文件格式混在了同一个字段？
11. 用户没提资料类型时，是否错误生成了默认类型？
