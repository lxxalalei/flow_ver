# Intent 语义理解与推断规则

## 1. Intent 的业务目标

Intent 不是分类器，也不是搜索器。它把家长或学习者的口语表达还原为下游能够使用的需求语义：学习主题、学习目标、使用者条件、资源偏好和不可违反的约束。

识别孩子想理解、探索、练习或实践的内容。根据用户表达和当前主题组织需求，不预设学科范围、资源形态或学习路径。

处理时先理解用户真正想解决的问题，再决定如何归一化字段。不要先套分类再解释用户。

## 2. 常见需求表达类型

### 直接资源型

用户已经说清资源对象：

- “想要恐龙科普动画”
- “找适合睡前听的历史故事”
- “找可以跟着做的天气小实验”

直接抽取主题、年级、形式和场景，通常无需澄清。

### 问题驱动型

用户描述问题，没有直接说资源名称：

- “孩子总分不清昆虫和蜘蛛” → 目标可能是理解分类特征和观察方法。
- “看历史故事记不住人物关系” → 目标是建立时间线和人物联系。
- “孩子不敢开口表达” → 目标可能是低压力表达、示范和参与活动。

将问题翻译为可学习的目标，但不要擅自诊断原因。证据不足时保留多个 related terms。

### 能力培养型

- “想培养专注力”
- “提高表达能力”
- “训练逻辑思维”

如果能力方向已经明确，可以搜索活动、训练和方法资源；只有能力名称过于宽泛且可能涉及多种路线时才澄清使用目标或场景。

### 内容主题型

- “想让孩子了解中国历史”
- “最近对太空很感兴趣”

核心主题明确时不要求用户先选课程、动画、书或音频。资源形态可动态覆盖。

### 多目标型

用户同时提出多个相关目标时，保留主目标和相关概念：

- “了解鸟类，还想学着观察记录” → core_topic 为鸟类观察，记录进入 learning_goal/use_scenario 或 related terms。
- “想了解太阳系，也想动手做行星模型” → core_topic 可概括为太阳系探索，模型制作进入学习目标和相关概念。

完全独立的多个目标不要强行合并；无法由一组候选共同覆盖时，使用 clarification 让 Flow 确认本次先处理哪一个。

## 3. 槽位定义

| 槽位 | 语义 | 典型来源 |
|---|---|---|
| `core_topic` | 孩子想理解、探索、练习或实践的主要内容 | 主题词、问题描述、明确目标 |
| `learning_domain` | 主题所属的上位知识或能力领域 | 自然、社会、人文、艺术、科技、语言、数学、生活知识等 |
| `target_age` | 内容理解、安全和表达方式所面向的年龄 | “5岁”“低龄”“小学生” |
| `grade_level` | 用户表达中与资源匹配有关的学习阶段信息 | “三年级”“小学高年级” |
| `learning_goal` | 用户希望通过资料实现的学习目的 | 了解、启蒙、探索、理解、实践、创作、巩固、系统学习等 |
| `difficulty` | 内容所需的理解基础和挑战程度 | 启蒙、基础、进阶；特定主题可使用更准确的领域表达 |
| `resource_types` | 视频类、音频类、文档类、练习类、图文类、图片类等资料大类 | 用户明确类型，或由明确形态/场景可靠归纳 |
| `format_preferences` | 动画、纪录片、公开课、试卷、练习册、绘本、课件等具体内容形态 | 用户明确形态，或由使用场景可靠推断 |
| `file_formats` | PDF、PPTX、DOCX、EPUB、MP3、MP4 等实际文件格式 | 用户明确文件后缀或格式名称 |
| `use_scenario` | 孩子或家长准备怎样使用资料 | 自主探索、亲子共读、路上听、跟做实践、打印使用等 |
| `version` | 能够区分资源内容或适用范围的版本信息 | 版次、册次、课程版或软件版本等 |
| `language` | 资源呈现语言 | 中文讲解、全英文、双语等 |
| `search_mode` | standard / exhaustive | “推荐几个”或“尽量全面” |

来源要求直接按强度写入 `constraints.must` 或 `constraints.prefer`，不再维护重复的 `source_preferences` 槽位。

## 4. 从口语到学习目标

| 用户表达 | 可推断 learning_goal | 不应额外推断 |
|---|---|---|
| “想先了解一下” | 初步了解 | 系统课程需求 |
| “最近很感兴趣” | 兴趣探索 | 固定学习路径 |
| “想跟着做一做” | 实践体验 | 必须使用视频 |
| “想自己讲给别人听” | 理解与表达 | 必须使用演讲课程 |
| “练练手”“刷几道题” | 练习巩固 | 竞赛难度 |
| “完全没接触过” | 启蒙 | 目标年龄 |
| “想系统学” | 系统学习 | 指定平台 |

推断时保留原始问题证据，不把模型解释写成用户原话。

## 5. 证据与状态

### explicit

用户直接表达或确认：

- “适合 8 岁孩子” → target_age explicit。
- “不要视频” → constraints.exclude explicit。
- “最好官方” → constraints.prefer explicit。

### inferred

由语义或稳定关系推出：

- 路上听 → 音频偏好 inferred。
- 练习题 → learning_goal=练习 inferred。
- 动画 → resource_types 包含视频类 inferred，同时 format_preferences=动画 explicit。
- PDF 试卷 → resource_types 包含文档类和练习类 inferred；试卷与 PDF 分别保留在具体形态和文件格式中。
- “想观察发芽过程” → learning_goal 可推断为观察与实践，但不要据此指定唯一媒介。

### defaulted

为了继续工作采用的低风险策略，不代表用户事实：

- 未指定搜索广度 → search_mode=standard。
- 普通儿童资源且无语言提示 → 可默认中文，但英语学习场景需谨慎。

资料类型、具体形态和文件格式不得仅因主题而 defaulted。用户说“形式都行”是明确授权，`resource_types=["不限"]` 应标记 explicit；多形态覆盖由 Search 规划。

### 未知值

没有足够依据时省略槽位：

- 主题明确但没年龄 → 省略 target_age。
- 没有能够区分资源内容或适用范围的版本证据 → 省略 version。
- “英语启蒙”但没说讲解语言 → 省略 language，或采用低风险 defaulted；不得标 explicit。

## 6. must、prefer、exclude

### must

不满足就不应进入最终候选：

- “只要免费的”
- “必须有操作步骤”
- “一定要可打印”
- “只要某个明确版本”

### prefer

可以妥协但应影响排序和路由：

- “最好带答案”
- “优先官方”
- “有动画更好”
- “尽量短一点”

### exclude

明确不接受：

- “不要视频”
- “不要付费”
- “别推荐短视频”
- “不需要家长课程”

否定范围必须精确。“不要太难”通常是难度偏好，不等于排除所有进阶内容；“不想只看视频”也不等于完全排除视频。

## 7. 冲突处理

- 两条使用者条件无法同时成立：都保留 explicit，记录冲突，必要时澄清。
- “只要免费，付费也可以看看”：must 语义冲突，需要澄清真实底线。
- “不要视频，最好是动画”：形式冲突，需要澄清。
- “官方优先，也接受老师经验”：不冲突，官方是 prefer，用户内容仍可作为补充。
- 历史上下文与当前请求冲突：当前请求优先，但用户已确认事实需要明确更新后才能覆盖。

## 8. 动态默认策略

默认不是固定模板，应考虑主题和场景：

- 需要事实准确性的主题：优先覆盖可核验来源。
- 需要方法与实践经验的主题：覆盖专业机构、可靠作者和真实经验。

只保留会实际影响搜索、筛选或使用的信息。不要使用固定默认补齐未知维度；主题适合哪些资料形态属于 Search 的召回策略，不是用户事实。

每个 defaulted 槽位都要在 assumptions 中解释。

## 9. Search 概念边界

Intent 输出概念材料，不输出查询任务：

```json
{
  "canonical_terms": ["火山", "地震", "儿童科普"],
  "synonyms": ["地质灾害", "地球活动"],
  "related_terms": ["板块运动", "火山喷发", "地震波", "安全避险"]
}
```

canonical terms 不得丢失用户核心语义；synonyms 是等价或近似表达；related terms 用于拓展但不能替代核心主题。

不得在这里选择平台、拼接完整搜索句或写 `site:`。

## 10. 输出前语义自检

1. core_topic 是否描述了用户真正想学或解决的对象？
2. 是否把问题描述误当成诊断结论？
3. explicit 是否都有原话证据？
4. inferred 是否与 explicit 分开？
5. defaulted 是否低风险且写入 assumptions？
6. 没有依据的槽位是否被错误填成看似完整的值？
7. must/prefer/exclude 是否保持了语气强度？
8. 是否还有会让 Search 走向完全不同路线的歧义？
9. 是否错误生成了平台或查询任务？
10. 是否把资料大类、具体内容形态和文件格式混在了同一个字段？
11. 用户没提资料类型时，是否错误生成了默认类型？
