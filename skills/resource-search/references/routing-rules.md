# 儿童学习资源的平台路由

本文件向模型提供儿童学习场景中的平台生态知识。它帮助模型推理，不定义“某个主题必须选择某个平台”的映射规则。

## 判断资源由谁使用

先判断预期使用者：

- 孩子直接使用：关注能否听懂、看懂、跟做、练习，以及表达方式和学习负担。
- 家长辅助使用：可以搜索陪伴方法、活动组织、资源比较和供家长准备的学习材料。
- 亲子共同使用：适合亲子阅读、共同观看、讨论、实验和活动。

同一主题在不同使用者和学习行为下可能需要完全不同的平台。不要把平台画像变成关键词后缀，也不要仅凭一个学科词决定平台。

## 判断平台价值

围绕当前需求推理：

1. 儿童希望完成什么学习行为：听、看、读、观察、比较、跟做、练习、创作、讨论或探索。
2. 哪种媒介最能帮助理解这个主题：声音、画面、故事、过程演示、文字材料、互动内容、实践活动或系统课程。
3. 需要快速了解、连续内容、系统学习，还是可反复使用的材料和活动。
4. 内容由孩子直接使用，还是供家长筛选和组织。
5. 哪个平台能提供其他任务没有覆盖的内容、媒介或来源。

据此选择主力平台和补充平台。平台数量随需求变化；没有独特贡献的平台不必加入。

## 平台内容生态

### bilibili

长于视频讲解、动画、过程演示、系列课程、合集和纪录片。适合需要画面辅助理解、观察变化、学习操作过程或连续观看的方向。内容深浅和创作者质量差异较大，Search 负责扩大召回，后续由 Selector 判断适龄性和质量。

### ximalaya

长于故事、朗诵、跟读、听书、儿歌、音频课和连续专辑。适合语言输入、听觉记忆、睡前或通勤等不便观看屏幕的场景，也可用于亲子共听。依赖图形和步骤展示的内容通常需要其他媒介补充。

### smartedu

长于结构化课程、学段学科内容、课件、讲义和练习资源。只在当前需求能从结构化教学内容、官方课程或配套材料中获得独特价值时选择，不把它作为所有儿童学习主题的默认来源。

### zhihu

长于方法解释、经验比较、资源线索和家长视角的问题讨论。主要用于家长理解“怎么陪、如何选择、如何帮助”，不能与孩子直接学习内容混为一类。

### douyin

长于短时间展示一个动作、技巧、步骤或趣味切面。适合快速示范和兴趣引入，不以承载完整知识体系为主要优势。平台内容和风控状态不稳定，是否加入还需结合可执行状态。

### weibo

长于机构账号发布、主题活动、公开资料线索和时效信息。适合寻找发布来源和活动线索，通常作为补充来源，而不是完整学习路径。

### open163

长于公开课、纪录片、讲座和较深入的人文、科学内容。更适合具备相应理解能力的儿童、青少年，或家长陪同观看的拓展学习。

### annas-archive

长于图书、电子书、长文和专业文章。只在阅读材料能够提供完整知识、故事叙述、图解说明或深入背景时选择；不因主题中出现“学习”“知识”等泛词自动加入。

### generic

通过通用搜索引擎发现机构网站、长尾网页、文章、文档、图片、活动方案和具体文件。它补充已接入平台没有覆盖的来源，并为每份搜索计划提供跨站探索。

## 从语义方案到可执行任务

先根据以上内容生态提出平台分工，再读取 `../config/platform-catalog.json`：

- 只保留 `planning_status=available` 的平台任务。
- 根据 `auth` 了解运行条件，但不要把认证信息写入计划。
- 只使用 `search_parameters` 声明的真实参数。
- 用户指定尚不可执行的平台时，可用 generic 搜索其公开网页，但不能伪造平台任务。

Catalog 是执行边界，不是路由算法。最终平台组合和查询角度由模型根据当前需求动态判断。
