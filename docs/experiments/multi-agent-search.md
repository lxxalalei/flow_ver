# Multi-Agent Search Planning Experiment

这是一项实验记录，不属于 `learning-resource-flow` 的默认行为。

目标只有一个：验证在少数复杂资源研究任务中，让一个或多个子 Agent **只辅助提出互补搜索方向**，是否能稳定提高最终候选质量。

基线始终是：

```text
Main Agent + semantic Skill + resource capabilities
```

只有满足下面条件时才值得实验：

- 任务本身包含多个真正独立、都较复杂的研究方向；
- Main Agent 单独规划时明显容易遗漏关键证据路线；
- 并行规划的收益可能高于额外上下文和调度成本。

子 Agent 只可以提出临时的搜索角度、来源职责和 query 建议。它不拥有资源状态，不执行下载/归档，也不能把自己的建议当成用户事实或真实搜索证据。

Main Agent 必须重新判断并裁剪子 Agent 输出，再决定是否实际搜索。

这项能力是否保留，应通过真实 OpenClaw A/B 评估，而不是因为实现存在就默认启用。建议比较：

- 需求理解是否更准确；
- 搜索方向是否更互补；
- query 是否更自然；
- 是否减少无效搜索；
- 最终候选质量是否提高；
- 额外上下文和调度成本是否值得。

如果没有稳定增益，默认保持单 Agent。
