# Selector 候选展示

展示目标是让用户基于已知事实做选择，不替资源补写宣传文案。

本文件说明模型向用户展示候选时的默认格式。Selector 已经在 `selector_review.json` 中完成排序和摘要，展示文本直接基于 `selector_review.json` 与 Stage 3 元数据组织。

## 展示模式

- `explore`：默认模式。用户想了解候选范围时，按资源类型分组展示候选。
- `recommend`：用户明确要模型推荐、挑选或直接决定时，从已审查候选中展示 3-5 个最值得且彼此互补的资源；合格候选不足时全部展示。先用一两句话说明该组合分别覆盖什么，再按下方四行格式列出。其余候选保留在 review 中，用户可以要求展开。

两种模式都不修改候选编号、评分或 review 内容。

## Explore 格式（按资源类型分组）

```text
共搜索到 {raw_count} 条；精确去重 {dedup_count} 条，过滤 {excluded_count} 条，保留 {candidate_count} 条。
平台异常：{没有则省略}

🎬 视频资源（{count} 条）

1. 🏷️ [A级 · 84分] 标题
   📝 一句话总结资源内容和特点
   🎬 来源：【Bilibili】视频 · 免费
   🔗 https://...

3. 🏷️ [B级 · 70分] 标题
   📝 一句话总结资源内容和特点
   🎬 来源：【Bilibili】视频
   🔗 https://...

🎵 音频资源（{count} 条）

2. 🏷️ [A级 · 80分] 标题
   📝 一句话总结资源内容和特点
   🎵 来源：【Ximalaya】音频 · 免费
   🔗 https://...

📖 图书与阅读（{count} 条）

...

回复编号选择，例如"1,3"；也可以回复"全部候选""只要视频"或"取消"。
```

### 分组顺序

视频资源 → 音频资源 → 图书与阅读 → 互动与练习 → 实验与活动 → 课程资源 → 网页与工具

### 分组标题行

`{type_icon} {category_name}（{count} 条）`，后接空行，然后是该组的候选。

## 展示规则

- S：90—100，A：75—89，B：60—74，C：40—59。
- 每条候选按四行展示，每行以 emoji 引导：
  1. `🏷️ [等级 · 分数] 标题` — 编号、评分等级和资源标题。
  2. `📝 {summary}` — 模型在 `selector_review.json:data.candidates[].summary` 中生成的一句话总结（不超过50字），描述资源是什么、适合谁或有什么特点。不是截取 description，而是模型理解后的概括。
  3. `{type_icon} 来源：【{platform}】{resource_type} · 免费/付费` — 来源行，type_icon 根据资源类型自动选择（🎬视频 🎵音频 📖图书与阅读 🧩互动与练习 🔬实验与活动 📚课程 🛠️网页与工具 📌其他）。免费/付费未知时省略。
  4. `🔗 {source_url}` — 资源链接。
- 不再输出"已知信息""推荐依据""注意"等额外行；这些信息保留在 `selector_review.json` 中供后续阶段使用。
- 没有证据的字段直接省略或写"未知"，不要写成"免费""可下载""适合某年龄"或确定的学习效果。
- `platform_signals` 只转述为播放量、收藏、集数等平台事实，不把它写成质量结论。
- `explore` 按资源类型分组展示候选；编号保持与 `selector_review.json:data.candidates` 一致。
- `recommend` 只展示 3-5 个模型综合挑选出的候选；不要机械选择分数最高的连续几项，优先形成互补组合，并提示用户可要求“展开其余候选”。用户回复“本轮推荐全选”时，只选择当前展示的编号；只有明确回复“全部候选”时才选择 review 中全部候选。
- 平台失败只说明影响，不把"未运行""零结果"和"认证失败"混为一谈。
- 不要改成 markdown 表格、只列标题链接，或压缩掉摘要与来源信息；保持四行格式，方便用户按编号选择。
