# Intent 澄清决策与话术规则

## 1. 澄清的唯一目的

澄清是为了避免 Search 搜到另一类资源，或被迫同时盲搜过多路线，不是为了完成问卷。只问“现在不确认就很可能走错方向或明显降低候选质量”的信息。

判断句：

> 如果不问这个问题，是否仍能生成一个方向明确、可筛选、不会明显偏离用户诉求的搜索计划？

- 能：不问，省略未知槽位，或使用有证据的 inferred、透明默认继续。
- 不能：澄清一个影响最大的点。

## 2. 澄清优先级

### P0：核心主题无法确定

必须问：

- “帮我找点资料”
- “想让孩子多了解一些”
- “想提升一下”但没有说明要提升什么

问题应让用户描述真实主题或痛点：

- “目前最想让孩子了解或学习什么？”
- “最想解决的是哪个具体问题？”

不要先问年龄、平台或资源形式。

### P0：多个目标无法共同处理

当用户同时提出彼此独立的主题，并且一组搜索计划无法合理覆盖时，只确认本次先处理哪个主题。单个宽泛主题如果路线分叉会显著影响搜索计划，按下一节澄清；如果用户明确授权“都可以”“先看看”“你决定”，再由 Search 使用多个角度探索。

### P0.5：主题明确但搜索路线分叉

主题已经可搜索，但路线差异会直接决定查询词、平台、候选类型或筛选标准时，先澄清最关键的一点。重点不是收集完整背景，而是减少 Search 的盲搜成本。

典型情况：

- 宽泛学科请求：如“一年级数学”“小学古诗文学习资料”。
- 能力培养请求：如“提高表达能力”“培养专注力”。
- 成长支持请求：如“情绪管理资源”“亲子沟通资料”。
- 补弱请求：如“孩子数学不太好，想补一补”。

问题应帮助用户选择搜索路线，而不是询问平台或资料格式：

- “这次数学资料更想找课内同步讲解、练习巩固，还是趣味数学拓展？”
- “古诗文资料这次更偏课内同步、朗读背诵，还是启蒙欣赏？”
- “数学补弱想先从计算基础、应用题，还是课内同步基础开始？”

以下情况不按路线分叉追问：

- 用户已经给出路线，例如“同步练习”“朗读背诵”“趣味启蒙”“可跟做活动”。
- 用户明确授权先看候选，例如“都可以”“先看看”“你决定”。
- 分叉只影响排序，Search 可以用少量互补查询覆盖。

### P0：用户明确事实冲突

例如：当前表达与已经确认的使用者条件、资源要求或版本信息无法同时成立。

问题应直接指出冲突并让用户确认哪一个有效，不要自行选择更常见的答案。

### P0：硬约束冲突

例如：

- “只要免费的，付费课程也可以”
- “不要视频，最好找动画”
- “必须可打印，只想要音频”

确认真正不能妥协的条件。软偏好之间可以并存，不需要澄清。

### P1：学习者信息确实改变内容路线

使用者信息通常不是第一问，但以下情况值得问：

- 同一主题面向不同年龄时，内容尺度、理解门槛或安全要求差异巨大。
- 用户要求“孩子自己看”，适龄和安全要求会直接影响候选。
- 缺少使用者信息会使资料无法安全、有效地使用。

以下情况不追问使用者信息：

- 主题可以多年龄覆盖并由 Selector 标注。
- 用户只是先看候选。

### P1：场景会决定资源媒介

只有资源形式会因此完全改变时才问：

- “想找英语材料”但已知场景是开车时使用 → 可直接推断音频，不问。
- “想找亲子活动”但不清楚是在家操作还是课堂使用 → 场景可能决定材料类型，可问。

## 3. 不应该澄清的情况

- "找恐龙成长资料"——主题已经可搜索，由 Search 规划互补形态。
- "推荐一些古埃及文明资料"——先用标准模式探索讲解、阅读和沉浸式内容。
- "你看着办""随便推荐"——采用透明默认，不要把决定权退回用户。
- "最好官方"——这是 prefer，不需要确认是否完全排除非官方。
- 没指定平台——平台路由属于 Search。
- 没指定数量——搜索预算属于 Search。
- 没指定下载格式——可在 Selector/Downloader 阶段处理。
- 用户没有指定资源形态——由 Search 选择与主题相关的互补方向。

## 4. 一次只问一个问题

错误：

> 想了解什么主题、孩子多大、喜欢视频还是音频、要不要付费？

正确：

> 目前最想让孩子了解或解决的具体内容是什么？

即使存在多个未知信息，也只问影响最大的一个。用户回答后继续当前 Intent 理解：把回答合并为增量证据，只更新受影响的语义，再判断是否还存在 P0 歧义。

## 5. 问题表达

问题应包含：

1. 用户能理解的自然语言。
2. 当前最可能的 2-3 个方向，帮助快速回答。
3. 允许自由回答，不强迫选固定分类。

示例：

- “目前最想让孩子了解或学习什么主题？”
- “这次最想先找鸟类观察资料，还是绘画入门资料？”
- “前后两条要求无法同时满足，这次以哪一条为准？”
- “你说不要视频但希望有动画，实际是完全不要视频，还是可以接受短动画讲解？”

不要说“请补充槽位”“请选择资源分类”“为了精准推荐请填写以下信息”。

## 6. 持续理解与停止条件

- 不设置固定澄清轮数。每轮收到回答后，结合刚才的问题更新同一份需求理解，只重新审视受新证据影响的部分和可能产生的冲突。
- 已确认且仍有效的主题、目标和约束继续成立；不要重复询问，也不要从空白重新抽取。
- 新证据足以形成合理搜索需求时结束澄清，不继续收集可选信息。
- 用户不知道某项信息但授权继续时，省略非关键维度，或使用安全且透明的低风险默认。
- 核心主题、硬约束或安全条件仍无法确定时继续自然追问，不为结束对话而编造信息。
- 用户明确取消或拒绝继续提供真正必要的信息时停止，不伪造 `ready` 需求。

## 7. 最终检查

提出问题前检查：

1. 不问时是否仍能生成合理、可筛选且不会明显偏离诉求的候选？
2. 是否可以通过互补召回和 Selector 选择解决？
3. 是否只是“能搜”，但路线太宽会让 Search 盲搜大量低价值方向？
4. 是否误把辅助维度未知当成必须澄清？
5. 是否一次问了多个问题？
6. 是否已有上下文证据可以回答？
